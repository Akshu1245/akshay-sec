THE PREMISE

What I wanted to solve

Security scanner output is difficult to act on when it gives a label but not the source of a finding or a reusable machine-readable report.

THE BUILD

How it works

A collection of small security utilities used to learn how findings are discovered, represented and reviewed. It includes a source-code auditor, a hash toolkit and an Nmap-to-JSON wrapper.

THE WALKTHROUGH

Follow the flow

01

Select

Point the auditor at code you own or are authorized to inspect.

02

Analyze

Run deterministic pattern checks for candidate risky constructs.

03

Review

Check the flagged locations and avoid assuming every match is a vulnerability.

04

Report

Export findings for inspection or a CI workflow.

IN THE REPOSITORY

What you can inspect

  • A source scanner for common secret, injection, configuration and crypto patterns.
  • Optional suggestions and limited auto-fix operations; every patch still requires review.
  • JSON and SARIF output for diagnostics and CI pipelines.
  • Complementary hash and network inventory scripts for lab environments.

BE HONEST ABOUT IT

Limitations and open questions

  • Rule-based tools produce false positives and false negatives.
  • Automated fixes can change semantics and must be reviewed.
  • Network scanning is limited to systems with explicit authorization.
