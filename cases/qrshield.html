CASE FILE / 01 · INTERNSHIP PROJECT

QRShield

A QR scanner that shows its reasoning.

Browser-based QR and link inspection with explainable warnings.

View source ↗Open project site ↗Try related demo →
PROJECT CONTEXTPublic demo + source · Cybersecurity internship project · Zephyr Technologies

THE PREMISE

What I wanted to solve

A binary 'safe / unsafe' label is hard to trust, especially for payment QR codes. People need to know which fields were read, which rules fired and which checks were not run.

THE BUILD

How it works

A QR code can hide a sign-in page, payment request or configuration payload. QRShield decodes the payload locally and describes the indicators it can detect. It deliberately avoids claiming that a link is safe.

THE WALKTHROUGH

Follow the flow

01

Decode

Read the QR content without automatically opening its destination.

02

Inspect

Classify URL, UPI or other supported payload; apply explicit checks.

03

Explain

Show signals, uncertainty and the inspection result in plain language.

04

Export

Generate a local report the user can review or share.

IN THE REPOSITORY

What you can inspect

  • Camera and image-based decoding in the browser using jsQR.
  • URL and UPI parsing with transparent rule-based findings.
  • Local scan history and text/PDF report export.
  • An optional server-side Web Risk URL lookup; when it is unavailable the interface reports 'not checked'.
  • Unit-test coverage for rules, history, reports and the threat-intelligence client.

BE HONEST ABOUT IT

Limitations and open questions

  • Heuristics cannot prove a URL is harmless.
  • Payment recipient ownership cannot be confirmed from a QR string.
  • Only an optional URL reputation query leaves the client; its result is not a guarantee.
